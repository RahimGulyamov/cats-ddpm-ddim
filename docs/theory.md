# Устройство обучения и генерации

## Прямой процесс

Для каждого изображения выбираются timestep `t` и независимый гауссов шум `ε`. Изображение на нужном уровне шума вычисляется сразу:

```text
αₜ = 1 − βₜ
ᾱₜ = ∏ᵢ₌₀ᵗ αᵢ
ε ~ N(0, I)
xₜ = sqrt(ᾱₜ) · x₀ + sqrt(1 − ᾱₜ) · ε
```

В коде `t` лежит в диапазоне 0…999. Индекс 0 уже содержит небольшой шум; чистое изображение находится перед первым переходом. Расписание `linear` задаёт β от 0.0001 до 0.02.

## Предсказание шума и MSE

U-Net получает `xₜ` и timestep embedding, возвращает `ε̂` той же формы. Уровень шума кодируется синусами и косинусами, затем MLP. В residual blocks embedding задаёт масштаб и сдвиг признаков. Skip connections передают пространственные детали из encoder в decoder, attention связывает удалённые области изображения.

```text
loss = mean((εθ(xₜ, t) − ε)²)
```

Истинный шум известен, потому что мы сами добавили его к изображению. Для гауссовой параметризации соответствующие слагаемые вариационной границы DDPM сводятся к квадратичным ошибкам с весами. Здесь используется упрощённая невзвешенная MSE. Случайный `t` позволяет учить все уровни шума без тысячи последовательных проходов сети на каждом batch.

Обновление включает backward, усреднение градиентов между DDP-процессами, clipping norm 1, AdamW и scheduler. EMA сглаживает веса и используется для validation и генерации. BF16 autocast применяется при обучении; validation и сравнение методов выполняются в FP32. Raw weights, optimizer, scheduler, RNG каждого rank и позиция потока данных сохраняются в `last.pt` для продолжения.

## DDPM

Начинаем с `x ~ N(0,I)`. Из предсказанного шума восстанавливаем оценку чистого изображения:

```text
x₀_hat = (xₜ − sqrt(1 − ᾱₜ) · ε̂) / sqrt(ᾱₜ)
```

Она ограничивается диапазоном `[-1,1]`. Обратный переход использует среднее апостериорного распределения и новый шум:

```text
μ = [sqrt(ᾱ_prev) · βₜ / (1 − ᾱₜ)] · x₀_hat
  + [sqrt(αₜ) · (1 − ᾱ_prev) / (1 − ᾱₜ)] · xₜ
β̃ = βₜ · (1 − ᾱ_prev) / (1 − ᾱₜ)
x_prev = μ + sqrt(β̃) · z,   z ~ N(0,I)
```

На последнем переходе свежий шум не добавляется. Реализован полный ancestral DDPM с 1000 соседними переходами. Попытка задать DDPM 50 шагов отвергается: сравнение ускоренных методов здесь проводится через DDIM.

## DDIM

Можно выбрать подмножество уровней `t > s` и перейти непосредственно к следующему выбранному уровню:

```text
σ = η · sqrt((1 − ᾱ_s)/(1 − ᾱ_t) · (1 − ᾱ_t/ᾱ_s))
x_s = sqrt(ᾱ_s) · x₀_hat + sqrt(1 − ᾱ_s − σ²) · ε̂ + σ · z
```

При `η=0` переход детерминирован для данных весов и начального шума. Начальный шум остаётся случайным. Уровни выбираются равномерно от 999 до 0, затем выполняется переход к чистому изображению. После clipping `x₀_hat` шум пересчитывается так, чтобы оставаться согласованным с этой оценкой.

Модель для DDPM и DDIM одна и та же: меняется только функция обратного перехода. Меньшее число вызовов U-Net обычно сокращает время генерации. Просто убрать случайный член из DDPM недостаточно для реализации DDIM.

## Валидация и ограничения метрик

Все 506 отложенных изображений AFHQ оцениваются на каждом из семи фиксированных уровней `t = 0,100,250,500,750,900,999`, с фиксированным шумом. В эксперименте few-shot аналогично проверяются все 16 holdout-изображений. Логируются noise MSE и ошибка восстановления `x₀`, с clipping и без него. Train использует случайный `t`, новый шум, отражения, dropout и raw weights; validation использует EMA и eval mode. Абсолютные средние этих двух кривых напрямую не сопоставимы. Динамика одной и той же validation между checkpoint сопоставима.

Маленькая ошибка предсказания шума не гарантирует качественную генерацию: ошибки обратных переходов накапливаются. Особенно на высоких уровнях шума маленькая ошибка ε может приводить к большой ошибке `x₀` из-за деления на `sqrt(ᾱₜ)`. Поэтому дополнительно оцениваются сетки и ошибки восстановления.

Nearest-train диагностика ищет ближайшую фотографию по RGB MSE, включая горизонтальные отражения. Все пары показываются без ручного отбора. Это способ визуально проверить запоминание, не FID и не формальный порог копирования. Отдельного test set нет.

## Воспроизводимость сравнения

DDPM и DDIM используют одинаковый EMA checkpoint, seed, размер batch и начальный CPU noise. Для шума обратных DDPM-переходов используется отдельный генератор. Перед каждым методом проводится прогрев; устройство синхронизируется перед и после измерения. Время включает обратные переходы и вызовы сети, исключает загрузку checkpoint, запись изображений и видео. Видео генерируется отдельным проходом; его длительность не служит измерением скорости.

Побитовая идентичность между CPU, CUDA и MPS либо разными версиями PyTorch не гарантируется.
